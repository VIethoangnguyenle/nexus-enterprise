## Backend

- **Migration `031_text_documents.sql`** (table `text_documents`: version, status check, 1 MiB check, owner FK; no OA column). Backup before: scratchpad `ngac-backup-before-031.sql`. Applied with `make db-migrate` (whole chain, idempotent) on `ngac`, and by psql on `ngac_ci`; table observed.
- **document service** `internal/texts` + `internal/rest/texts_handler.go`, wired in `cmd/main.go` (new policy client, `POLICY_SERVICE_ADDR` added to Makefile dev target and docker-compose). Routes: `GET|POST /workspaces/:id/documents/texts`, `GET|PATCH|DELETE /documents/texts/:docId`.
  - Authorization on the document's **parent OA** (folder OA, or `workspaces.documents_oa_id`), resolved at request time by join so a trashed/deleted folder removes access; `read` for get/list, `write` for create/patch/delete; list is one `BatchCheckAccess` for read+write and fails closed. A missing document and a forbidden one answer alike (403). All constants from `backend/ngac` (`make check-ngac` passes).
  - Optimistic concurrency: `UPDATE ... WHERE id AND version = $base` in one statement, result read in the same transaction (a later writer's version can never be adopted as base). 409 body: `{reason:"version_conflict", current:{...}}`, sent only after the `write` check.
  - Limits: title 1-200, content 1 MiB (route `BodyLimit` 2M, DB check, UTF-8/NUL), status enum, `scope` enum, at least one field. Unexpected errors: generic `internal error`, logged. Owner names only for people in `tenant_users` of that workspace.
- **workspace service**: `Service.WorkspaceDetails` (member) and `UpdateWorkspaceDetails` (`manage` on Mgmt OA, validated, trimmed, partial) + `GET|PATCH /workspaces/:id/details` on `AdminHandler`; `GetByID` now returns the description; row added to the existing `adminCases` table so the deny-matrix (member, outsider, other workspace's owner, other-op holder, no caller, PDP error) runs over it.
- Vite proxy: no change needed. `/api/workspaces/:id/documents/texts` hits the existing `/documents` regex block, `/api/documents/texts/:id` the `/api/documents` prefix, `/api/workspaces/:id/details` the workspace default, `/api/me/profile` the existing `/api/me`; Traefik rules for document/workspace already cover them.

## Decisions where the mockup was silent or the API could not follow

1. Văn bản table holds **in-app documents only**; uploaded files stay in the folder views (mockup §2 shows both in one table with upload progress). Merging means a second listing and an upload row model; the drive already does upload well. Not built.
2. The group links are "Tất cả văn bản / Bản nháp của tôi / **Được chia sẻ**" (not "…với tôi"), so they cannot be confused with the drive's existing "Được chia sẻ với tôi" link. Shared = written by someone else and readable.
3. Docs are created only at the top of Documents from the UI (a doc inside a folder would be invisible in the folder table). The service supports `folder_id` (deny-tested).
4. "Văn bản mới" is always shown; a caller without `write` gets the shared 403 toast ("Bạn chưa có quyền tạo văn bản…").
5. Delete is permanent behind a confirm that says so (there is no trash for text documents; Undo would need one).
6. Department filter uses the departments that people's profiles carry (flat chip with counts), not the admin tree: the contacts API returns the free-text `users.department`, not the org tree id.
7. Settings tab order follows the mockup (Hồ sơ, Workspace, Giao diện), not the order in the brief.
8. "Nơi làm việc" (location) replaces the mockup's optional phone number in Hồ sơ: the profile API has no phone.
9. Contacts view toggle (bảng/thẻ) is the segmented control from §1 callout 1, stored with the other preferences. Presence label does not fade (no animation on presence text).
10. Editor header shows owner and "Sửa lần cuối": the API has no last editor name.
