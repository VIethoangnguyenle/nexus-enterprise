# Phase 10: Quản trị › Danh bạ

## Overview
Admin screen for the two rule types, rendered from the admin.html section approved in phase 01. Spec: `admin-screens`.

## Requirements
- Route `/admin/directory` (org workspaces with `manage`; the admin frame's existing 403 handling applies). Nav entry
  "Danh bạ" in `AdminFrame.tsx`, also in tablet/phone admin navigation as the mockup shows.
- Header text "Mặc định mọi thành viên thấy toàn bộ danh bạ. Quản trị viên luôn thấy tất cả."
- List "Phòng ẩn khỏi danh bạ · N": department name, "Chỉ N người trong phòng và quản trị viên thấy", Bỏ ẩn (confirm).
  "Ẩn một phòng" → `DepartmentPicker` (`components/admin/DepartmentPicker.tsx`); hiding a department implies its subtree
  (say so in the confirm).
- List "Chỉ thấy phòng của mình · N": "Vai trò X" / "Phòng Y", "N người · thấy người trong phòng của họ", Bỏ.
  "Thêm vai trò hoặc phòng" → `RolePicker` (custom roles only) or `DepartmentPicker`.
- Loading, empty, error (+ Thử lại) states; success/failure toasts in words; never IDs, never typed names. A 503 from the
  rules endpoint (workspace without directory nodes, release-A window before 064) renders the error state (plan Q4).
- Mutations from `hooks/useAdmin.ts` (phase 06) invalidate departments, contacts, rules.

## Architecture
- New `components/admin/DirectoryScopeScreen.tsx` + `DirectoryScopeScreen.test.tsx`;
  `routes/_workspace/admin/directory.tsx` (TanStack file route; `routeTree.gen.ts` regenerated by the router plugin, not
  hand-edited).

## Success Criteria
- An admin hides a department and a plain member's Danh bạ (another browser) loses it after refetch/realtime event.

## Risk Assessment
- Admin limits a role they hold themselves (Low×Low): admins keep the shortcut; no lock-out possible.
- Rollback: revert; rules already set remain enforced by backend (can be cleared via API).
