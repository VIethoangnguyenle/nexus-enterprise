# Task Completion Checklist

No pre-commit hooks or CI enforcement in the repo — these are manual and skipping them is how breakage lands.

## Backend change

1. `make build-check` — all 8 services must compile.
2. `make test` (or `make test s=<service>` when the blast radius is one service).
3. If a `.proto` changed: `make proto` **and** `cd frontend && npm run proto:gen`. Regenerating only one side leaves the wire contract silently skewed.
4. If NGAC operations or node names changed: confirm every new string originates from `backend/ngac` — the package exists so a rename is a compile error rather than a runtime permission bug.
5. If `data/init.sql` changed: `make db-migrate` against the running DB.

## Frontend change

1. `cd frontend && npm run lint`
2. `cd frontend && npm test`
3. If a new REST path was added: add it to the Vite proxy table in `frontend/vite.config.js`, otherwise it 404s in dev while working in Docker (see `mem:frontend/core`).
4. Never hand-edit `src/routeTree.gen.ts`; it is regenerated by the router plugin on the next dev/build.

## Full-stack change

Run `make build-check` and both test suites, then exercise the path against `make run` — the compose and native-dev topologies use different ports, and only the native one matches the Vite proxy table.
